# 未来方案：真机长程记忆模型架构

## 1. 目标

在真机连续执行和反复重规划时，模型需要记住当前画面之外的任务历史，例如物体曾经的位置、已经执行的操作以及任务进展。

该记忆跨越真实控制时刻 `t`，不等同于一次 C-JEPA 调用内部的 rollout round `r`：

```text
r：模型内部对一条候选动作进行多轮未来预测
t：真机实际观测、规划、执行之后进入的下一个控制时刻
```

长程记忆只沿真实时间 `t` 更新，并在同一 episode 内持续保留。

## 2. 总体架构

```text
真实观测 obs_t + 上一步实际执行的 action_(t-1)
                         │
                  observation encoder
                         │
                 memory input e_t^obs
                         │
h_(t-1) ───────────► stateful GRU ───────────► h_t
                                               │
                                               │ 只读
候选动作 A_t^j                                  │
      │                                        │
当前 C-JEPA action-conditioned rollout          │
      │                                        │
rollout_trace_t^j                               │
      │                                        │
trajectory encoder → candidate feature c_t^j ──┘
                         │
                  memory-conditioned fusion
                         │
                 monotonic quantile readout
                         │
                 q10_t^j / q50_t^j / q90_t^j
```

每条候选动作仍然只输出一组整体回报分位数。`h_t` 表示真实 episode 历史，`c_t^j` 表示第 `j` 条候选动作的预测未来。

## 3. 记忆更新

### 3.1 记忆输入

记忆输入只来自已经发生的真实信息：

```text
e_t^obs = MemoryInputEncoder(
    current object slots,
    current proprio / 末端实际位姿,
    previous executed action
)
```

其中 previous executed action 是机械臂末端期望位姿增量。可选地加入上一步观测到的 reward，但不加入成功/失败标签。

### 3.2 状态更新

```text
h_t = GRUCell(e_t^obs, h_(t-1))
```

GRU 每个真实控制时刻只更新一次。所有候选动作共享同一个 `h_t`，候选轨迹只能读取记忆，不能修改记忆。

这样可以避免把尚未执行的想象轨迹写入长期状态，也避免候选动作的评分顺序改变最终结果。

## 4. 候选动作评分

对控制时刻 `t` 的第 `j` 条候选动作：

```text
rollout_trace_t^j = CJepaRollout(obs_t, A_t^j)
c_t^j = TrajectoryEncoder(rollout_trace_t^j)
f_t^j = Fusion(c_t^j, h_t)
```

`TrajectoryEncoder` 负责压缩一次调用内部的预测轨迹；`Fusion` 可先使用简单的拼接和 MLP：

```text
f_t^j = MLP([c_t^j ; h_t])
```

后续如需更强交互，再改为由 candidate tokens 对 memory tokens 做 cross-attention。

输出继续采用单调分位数参数化：

```text
q50 = median_head(f50)
q10 = q50 - softplus(lower_gap_head(f10))
q90 = q50 + softplus(upper_gap_head(f90))
```

## 5. 真机推理状态机

```python
h = zeros()                         # episode 开始
previous_action = zeros()

while not episode_done:
    obs = robot.observe()
    e_obs = encode_memory_input(obs, previous_action)
    h = gru_cell(e_obs, h)           # 每个真实时刻只更新一次

    scores = []
    for candidate in candidate_plans:
        trace = cjepa_rollout(obs, candidate)
        scores.append(score(trace, h))  # h 只读

    selected = select_plan(scores)
    previous_action = robot.execute(selected.first_action)
```

以下情况必须重置 hidden state：

- 新 episode 或新任务开始；
- 环境被人工复位；
- 控制中断后无法确认状态连续性；
- 对应并行环境被替换。

并行真机或并行环境需要按 `env_id` 分别保存 `h_t`。

## 6. 训练数据与损失

训练样本必须保留同一 episode 内的时间顺序：

```text
episode_id
obs[0:T]
proprio[0:T]
executed_action[0:T]
candidate_action[0:T, ...]
return_to_go[0:T, ...]
```

不能只把所有控制时刻打乱为互不相关的单帧样本，否则 GRU 学不到跨时刻记忆。训练时使用 episode sequence 或连续 chunk，并在 episode 边界清空 hidden state。

推荐使用 truncated BPTT：

```text
前 K_burn 步：只建立 hidden state，可不计评分损失
后 K_train 步：计算 quantile loss
每个 chunk 结束：detach hidden state
```

主损失保持不变：

```text
loss = loss_quantile + λ_anchor × loss_anchor
```

其中 `loss_quantile` 在连续控制时刻上计算；现有 C-JEPA anchor loss 仍只约束 world model，不承担长程记忆监督。

## 7. 与当前方案的边界

当前方案中的 GRU 聚合一次候选动作预测里的 rollout rounds，hidden state 在单次 forward 内产生并结束。

本未来方案新增的 stateful GRU 聚合真机真实控制时刻，hidden state 需要跨多次 forward 保存。两者时间轴不同，不能通过保留当前 forward 内部 GRU 的最终状态直接等价替代。

该方案属于未来扩展，当前代码不实现。
