# SPAVR 代码实现计划

## 1. 分层原则

- `spavr/` 是纯 PyTorch 网络，负责构造 C-JEPA、预测未来 latent 和输出奖励/风险分位数；训练和普通推理共用同一个 `forward`。
- `train/` 负责滑动窗口 Dataset、冻结策略、联合损失、优化器分组和 TensorBoard 日志。
- `third_party/cjepa/` 只导入，不修改。
- 原始像素和预抽取对象 slots 共用同一个 predictor 与分位数头。
- checkpoint 权重读取、数据集路径和 Trainer 参数由训练入口配置，不写进网络 forward。

## 3. 模块职责

### `spavr/backbone.py`

`CJepaBackbone` 内部持有完整 `CausalWM_AP`：

```text
encoder + initializer + slot_attention
predictor + action_encoder + proprio_encoder
```

公开接口只有三项：

- `encode_inputs(batch, num_steps)`：当 batch 含 `pixels_embed` 时直接使用预抽取 slots；否则通过 `CausalWM_AP.encode` 从 `pixels` 提取 slots。两条路径都会拼入 proprio/action 槽。
- `forward(batch)`：消费完整长度 L 的未来动作序列，按官方 AP 顺序迭代 predictor、写入动作并滚动 history；动作耗尽后额外预测一次，返回 `(B,P,S+2,D)`。调用次数为 `ceil((L-H)/P)+1`。
- `anchor_loss(batch)`：使用 H+P 帧真值计算 masked-history、future-object 和 future-proprio MSE。

默认 `H=5`、`P=3`、`S=4`、`D=128`。动作输入只表示未来动作，长度 L 可变且必须至少为 H；backbone 消费传入的完整序列。训练数据默认 L=H+P=8，因此调用两次 predictor。

### `spavr/model.py`

`RewardRiskModel.forward(batch)` 只执行：

```text
CJepaBackbone(batch) → z_future (B,3,6,128)
QuantileHead(z_future) → [q10,q50,q90] (B,3)
```

它不包含 loss、优化器、日志和训练循环，因此可直接用于推理和导出。

### `train/train.py` 统一训练入口

训练入口根据 `training.stage` 选择 `dynamics`、`quantile_head` 或 `joint`，负责构建对应 Dataset、冻结模块、创建 optimizer/scheduler、验证、TensorBoard 和 checkpoint。阶段配置位于 `configs/spavr_stages/`。

`RewardRiskModel.compute_loss` 返回：

```text
quantiles
loss_quantile
loss_future_object
loss_future_proprio
loss_masked_history
loss_total
```

只计算当前阶段权重大于零的 loss；3A 不需要 `return_to_go`，3B 不重复计算 latent supervision。

## 4. 三段训练策略

### 3A Dynamics

```text
冻结：VideoSAUR / object slots / QuantileHead
训练：predictor / action_encoder / proprio_encoder
loss：future object + future proprio + masked history
```

配置：`configs/spavr_stages/01_dynamics.yaml`。

### 3B Quantile Head

```text
加载：3A best.pt
冻结：完整 dynamics
训练：QuantileHead
loss：pinball
```

配置：`configs/spavr_stages/02_quantile_head.yaml`。

### 3C Joint Finetune

```text
加载：3B best.pt
训练：predictor / action_encoder / proprio_encoder / QuantileHead
loss：pinball + 低权重 latent supervision
optimizer：dynamics lr=1e-5，head lr=1e-4
```

配置：`configs/spavr_stages/03_joint_finetune.yaml`。

## 5. 数据契约

训练可选原始像素：

```python
batch = {
    "pixels":       ...,  # (B,H+P,3,H_img,W_img)，frozen 无 anchor 时可仅 H 帧
    "proprio":      ...,  # (B,H+P,7)
    "action":        ...,  # (B,L_action,7)，L_action >= H
    "return_to_go": ...,  # (B,)
}
```

或预抽取 slots：

```python
batch = {
    "object_slots": ...,  # (B,H+P,S,D)
    "proprio":      ...,  # (B,H+P,7)
    "action":        ...,  # (B,L_action,7)
    "return_to_go": ...,  # (B,)
}
```

预处理 episode 中的外部视频、proprio、action、reward 和 timestamp 均为 `T` 步。训练 Dataset 在此基础上按历史边界切出状态历史和未来动作窗口。

实际部署推理只需 H 帧状态和至少 H 个未来动作块；更长的 VLA 动作序列会被完整 rollout，不再截断到 H+P。

## 6. 三阶段启动方式

```bash
spavr-train --config configs/spavr_stages/01_dynamics.yaml
spavr-train --config configs/spavr_stages/02_quantile_head.yaml
spavr-train --config configs/spavr_stages/03_joint_finetune.yaml
```

每个阶段都保存 `metrics.jsonl`、`last.pt`、`best.pt` 和 TensorBoard 日志。阶段切换读取上一阶段 `best.pt` 的模型权重，并创建新的 optimizer/scheduler。

`CJepaBackbone` 不接收外部 `visual_model`、`world_model` 或 VideoSAUR 配置文件。DINOv2 encoder、投影 MLP、RandomInit、SlotAttention、VideoSAUR 时序 processor 与 `CausalWM_AP` 都在代码中按固定结构创建；不会额外创建无用的 VideoSAUR decoder、loss 和 optimizer。指定 `cjepa_model_object` 时，训练入口只从官方保存对象中提取并加载参数。checkpoint 的 H、P、slot 数量、slot 维度、action 输入宽度和 proprio 维度必须与当前配置一致。
