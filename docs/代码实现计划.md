# SPAVR 代码实现计划

## 1. 分层原则

- `spavr/` 是纯 PyTorch 网络，负责构造 C-JEPA、预测未来 latent 和输出奖励/风险分位数；训练和普通推理共用同一个 `forward`。
- `train/` 负责 Stable-Pretraining 集成，包括冻结策略、联合损失、优化器分组和训练日志。
- `third_party/cjepa/` 只导入，不修改。
- 原始像素和预抽取对象 slots 共用同一个 predictor 与分位数头。
- checkpoint 权重读取、数据集路径和 Trainer 参数由训练入口配置，不写进网络 forward。

## 3. 模块职责

### `spavr/backbone.py`

`CJepaBackbone` 内部持有完整 `CausalWM_AP`：

```text
encoder + initializer + slot_attention
predictor + action_encoder + proprio_encoder
```

公开接口只有三项：

- `encode_inputs(batch, num_steps)`：当 batch 含 `pixels_embed` 时直接使用预抽取 slots；否则通过 `CausalWM_AP.encode` 从 `pixels` 提取 slots。两条路径都会拼入 proprio/action 槽。
- `forward(batch)`：消费完整长度 L 的未来动作序列，按官方 AP 顺序迭代 predictor、写入动作并滚动 history；动作耗尽后额外预测一次，返回 `(B,P,S+2,D)`。调用次数为 `ceil((L-H)/P)+1`。
- `anchor_loss(batch)`：使用 H+P 帧真值计算 masked-history、future-object 和 future-proprio MSE。

默认 `H=5`、`P=3`、`S=4`、`D=128`。动作输入只表示未来动作，长度 L 可变且必须至少为 H；backbone 消费传入的完整序列。训练数据默认 L=H+P=8，因此调用两次 predictor。

### `spavr/model.py`

`RewardRiskModel.forward(batch)` 只执行：

```text
CJepaBackbone(batch) → z_future (B,3,6,128)
QuantileHead(z_future) → [q10,q50,q90] (B,3)
```

它不包含 loss、优化器、日志和训练循环，因此可直接用于推理和导出。

### `train/common.py` 与两个训练入口

`common.py` 中的模型构建、PushT slot DataModule、Stable-Pretraining forward 和 Manager 启动逻辑同时被两个策略复用。`train_frozen.py` 固定选择 Frozen，`train_finetune_predictor.py` 固定选择 Predictor，不提供一个脚本内混选策略的接口。

Stable-Pretraining forward 返回：

```text
quantiles
loss_quantile
loss_anchor       # predictor 策略且 anchor_weight>0 时
loss
```

训练、验证和预测 stage 使用同一个包装层；`stage="predict"` 不要求 `return_to_go` 标签。

## 4. 两种训练策略

### Frozen

```text
EvalOnly(整个 backbone)
训练：QuantileHead
loss：pinball
optimizer：head_opt
```

配置：`configs/frozen.yaml`。

### Predictor

```text
EvalOnly：encoder / initializer / slot_attention
训练：predictor / action_encoder / proprio_encoder / QuantileHead
loss：pinball + anchor_weight × anchor_loss
optimizer：head_opt + dynamics_opt
```

配置：`configs/finetune_predictor.yaml`。

Stable-Pretraining 负责 manual optimization、多优化器 step、梯度累积、裁剪、scheduler、DDP 和 checkpoint。

## 5. 数据契约

训练可选原始像素：

```python
batch = {
    "pixels":       ...,  # (B,H+P,3,H_img,W_img)，frozen 无 anchor 时可仅 H 帧
    "proprio":      ...,  # (B,H+P,4)
    "action":        ...,  # (B,L_action,6)，L_action >= H
    "return_to_go": ...,  # (B,)
}
```

或预抽取 slots：

```python
batch = {
    "pixels_embed": ...,  # (B,H+P,S,D)
    "proprio":      ...,  # (B,H+P,4)
    "action":        ...,  # (B,L_action,6)
    "return_to_go": ...,  # (B,)
}
```

实际部署推理只需 H 帧状态和至少 H 个未来动作块；更长的 VLA 动作序列会被完整 rollout，不再截断到 H+P。

## 6. Stable-Pretraining 启动方式

```bash
# 策略1，只读取 configs/frozen.yaml
python -m train.train_frozen \
  data.embedding_dir=/path/slots.pkl \
  data.action_dir=/path/actions.pkl \
  data.proprio_dir=/path/proprio.pkl \
  cjepa_model_object=/path/cjepa_object.ckpt

# 策略2，只读取 configs/finetune_predictor.yaml
python -m train.train_finetune_predictor \
  data.embedding_dir=/path/slots.pkl \
  data.action_dir=/path/actions.pkl \
  data.proprio_dir=/path/proprio.pkl \
  cjepa_model_object=/path/cjepa_object.ckpt
```

数据集、DataLoader、Lightning Trainer 和真实 checkpoint 路径依赖具体训练环境，保持在训练入口中，不放进 SPAVR 网络包。

`CJepaBackbone` 不接收外部 `visual_model`、`world_model` 或 VideoSAUR 配置文件。DINOv2 encoder、投影 MLP、RandomInit、SlotAttention、VideoSAUR 时序 processor 与 `CausalWM_AP` 都在代码中按固定结构创建；不会额外创建无用的 VideoSAUR decoder、loss 和 optimizer。指定 `cjepa_model_object` 时，训练入口只从官方保存对象中提取并加载参数。checkpoint 的 H、P、slot 数量、slot 维度、action 输入宽度和 proprio 维度必须与当前配置一致。
